## 4. Revisão de segurança e privacidade

1. **Hash de senhas:** Implementado via `node:crypto.scrypt` com salt criptográfico de 16 bytes e 64 bytes de chave derivada.
2. **Sessão:** Tokens pseudo-aleatórios de 32 bytes gerados via `node:crypto.randomBytes`, armazenados no banco apenas na forma de hash SHA-256 (`hashSessionToken`). Cookies emitidos com `HttpOnly`, `SameSite=Lax` e `Path=/`.
3. **Proteção contra escalonamento:** O payload de `POST /api/auth/register` define fixo `role: 'student'`. Contas com papel `admin` são inseridas unicamente via seed/script autorizado (`npm run seed:admin`).
4. **Isolamento de dados:** `GET /api/me` e `GET /api/admin/users` usam função `publicUser()` que estritamente filtra `password_hash`, `password` e tokens internos.
5. **Autonomia do site estático:** O frontend verifica a disponibilidade do backend e, caso esteja operando em modo estático puro (GitHub Pages sem backend ativo), mantém todas as lições acessíveis e exibe mensagem informativa amigável no modal de conta sem falhar.
